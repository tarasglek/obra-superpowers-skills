# Brainstorming Context Research Design

For substantive features, bugs, architecture changes, or unfamiliar areas, expand brainstorming's existing project-context step before clarification or design.

Research remains one compact checklist item:

1. inspect repository state and relevant Git/path history;
2. search prior local Pi sessions for decisions and unfinished work;
3. when a GitHub/GitLab remote exists, search related open and closed issues and PRs/MRs;
4. use Brave Search for current primary sources, comparable implementations, and known pitfalls;
5. summarize reusable findings and verify historical claims against the current tree.

Skip this expanded research for trivial edits and docs. Missing sessions, forge authentication, or web search should be reported but must not block planning. No new skill is introduced; `brainstorming` remains the reliable trigger.
